Your 4 MetaMask wallets: what each one is for

DeployerOwns ZeetoCheckout (pause, ownership). Not used day to day. Keep its key off servers.
RelayerIts private key goes in Vercel as RELAYER_PRIVATE_KEY. Holds only WBT for gas. Pays gas for every customer.
MerchantNot needed by the app: a stall is paid to the wallet Zeeto makes when the merchant signs in. Keep it for the faucet.
Customer (100 USDT)Send 20–50 USDT from it to your Zeeto wallet once (step 7). After that, paying is one tap, no gas.

Why not log in with MetaMask directly? Zeeto's payer flow signs with the wallet made at phone/email sign-in, so the customer never sees gas, chains or pop-ups. MetaMask is just where your test USDT starts.

You do (in order)

  1. Push the latest code blocks

    From the repo root on your Mac. Three commits, author is only you:

    cd ~/Desktop/zeeto
git add apps/mobile && git commit -m "feat(mobile): role choice + sign-in on first open, real stalls, MetaMask top-up note"
git add apps/web/src && git commit -m "feat(web): start screen with role choice and sign-in, MetaMask top-up"
git add -A && git commit -m "feat(whatsapp): Gemini listings from photos and free-text commands; docs, offline test"
git push

    Checkgithub.com/vij-sameerb5/zeeto shows the commits; git status is clean.

  2. Import the repo on Vercel blocks

    vercel.com → Add New → Project → vij-sameerb5/zeeto. Root Directory: apps/web, keep "include files outside root" on, leave build settings as detected (they come from apps/web/vercel.json).

    Environment variables (type them into Vercel's form):
    Browser: VITE_PRIVY_APP_ID VITE_MAPBOX_TOKEN VITE_MAPBOX_STYLE VITE_ADMIN_USERS
    Server only: PRIVY_APP_ID PRIVY_APP_SECRET SUPABASE_URL SUPABASE_SECRET_KEY CHECKOUT_ADDRESS RELAYER_PRIVATE_KEY ADMIN_USERS GEMINI_API_KEY WHATSAPP_TOKEN WHATSAPP_PHONE_NUMBER_ID WHATSAPP_APP_SECRET WHATSAPP_VERIFY_TOKEN

    CHECKOUT_ADDRESS = 0xB3D0d4FB70f1C09C311194E322CDE225eCf3f22f. Your local .env.local is missing the PRIVY / SUPABASE server ones: copy them from the Privy and Supabase dashboards.

    CheckThe deployment says Ready and the site opens.

  3. Set SITE_URL, redeploy, allow the origin in Privy blocks

    Add SITE_URL = your production URL (e.g. https://zeeto-xxx.vercel.app) → Deployments → Redeploy. In dashboard.privy.io → your app → Allowed origins: add the same URL.

    CheckOn the live site, /start → "Continue with phone or email" opens Privy and an OTP arrives.

  4. Read /api/health blocks

    Open <your-url>/api/health.

    Checkfeatures: auth, db, checkout, relay, ai, whatsapp all true; site is your URL; relayer is your relayer address. Any false = that env var is missing or misspelled.

  5. Open your first real stall

    Phone A: site → /start → "I run a stall or shop" → sign in (phone or email) → Join → name, category, photo, WhatsApp number with +91 → Go live.

    CheckThe stall shows on /explore from another browser, and Admin → Stalls lists it.

  6. Sign in as a customer

    Phone B (different number or email): /start → "I'm shopping" → sign in. Go to Wallet and copy your address.

    CheckWallet shows "Live · chain 1874" and your address.

  7. Move test USDT from MetaMask to that wallet blocks

    Wallet → "Add USDT from MetaMask" shows a QR. In MetaMask (customer wallet, Whitechain Testnet 1874) send 20–50 USDT to it. No WBT needed.

    CheckZeeto Wallet shows the USDT balance after a few seconds.

  8. First real gas-free payment blocks

    Phone B: open the stall → add an item → Pay. Or scan the stall's QR → ₹20 → Pay. Phone A: accept → ready → hand over.

    CheckThe receipt link opens Whitechain's explorer: the tx was sent by the relayer, calls ZeetoCheckout, and has a Paid event. The customer's WBT balance did not change. Paste the tx link into the README "Deployed" table.

  9. Switch on WhatsApp

    developers.facebook.com → Business app → WhatsApp → API setup: token, phone number ID; App settings: app secret. Put them in Vercel (step 2) and redeploy. Configuration → Webhook: <url>/api/whatsapp, verify token = your WHATSAPP_VERIFY_TOKEN, subscribe to messages. Add each demo phone as a test recipient; each sends hi once (Meta only allows replies within 24 h of their last message).

    CheckFrom phone B send pay <stall name> 20 → a Pay button. From the stall's WhatsApp send a photo of stock → AI listing → publish → items on the stall page. Try chai kahan milegi?.

  10. Point the phone app at the site

    Create apps/mobile/.env with one line: EXPO_PUBLIC_WEB_URL=https://<your-url>. Then cd apps/mobile && npx expo start --tunnel -c.

    CheckThe app opens on "How will you use Zeeto?" → pick → sign in → comes back with your wallet address on the Wallet tab; real stalls show on Explore.

  11. Retry contract verification

    Blockscout was down earlier. From contracts/:

    forge verify-contract 0xB3D0d4FB70f1C09C311194E322CDE225eCf3f22f src/ZeetoCheckout.sol:ZeetoCheckout \
  --chain-id 1874 --verifier blockscout --verifier-url https://explorer.testnet.whitechain.io/api/ \
  --constructor-args 0x000000000000000000000000cedfb56113143d55b2358b8cfbb0deb5ad2f55a7

    CheckThe contract page on the explorer shows a green "Verified" and the source.

  12. Record the demo and submit

    2–4 minutes: customer and stall side by side → pay → explorer → refund → WhatsApp pay + photo listing → store checkout example. Submit on ETHGlobal with the repo, live URL, contract address, tx link.

    CheckSubmission page shows Whitechain · Operate track selected and the video plays.
